Tutorial

Create your first shared board

Create a Build → Review workflow, change a selected box with an agent, and export a picture.

1. Prepare the binaries and data directory

Complete the installation guide. Add the extracted bin directory to PATH. Choose an absolute directory for board data, such as /home/you/boards. Keep it outside the release archive.

2. Connect one MCP client

Configure your agent client to launch this executable:

/absolute/path/boardmesh-linux-x86_64/bin/boardmesh-mcp   --sessions-dir /home/you/boards --session default

The client must initialize MCP and keep stdio open. For a client that uses the common mcpServers JSON format, the equivalent entry is:

{
  "mcpServers": {
    "boardmesh": {
      "command": "/absolute/path/boardmesh-linux-x86_64/bin/boardmesh-mcp",
      "args": ["--sessions-dir", "/home/you/boards", "--session", "default"]
    }
  }
}

Use your client's own configuration location and restart instructions. Boardmesh does not choose that location. Ask the agent to list its available Boardmesh tools and call get_tool_help. A connected server advertises 40 tools in this release.

3. Create a new board

Ask the agent:

Create a new Boardmesh session named first-board and make it active.
Use create_session. Do not clear or replace an existing board.
If first-board already exists, stop and ask me for a new name.

The tool call is:

create_session {"session_id":"first-board","make_active":true}

Now open the same board in the desktop:

boardmesh --sessions-dir /home/you/boards --session first-board   --runtime-url ws://127.0.0.1:9467

You see an empty board. The status bar identifies the session and shows the MCP connection. If it says MCP offline, follow the connection checks before continuing.

4. Ask for a first draft

Give the agent this prompt:

On first-board, draw two boxes: Build at [100,140,220,120] and
Review at [540,140,220,120]. Add their labels and a straight line
from [320,200] to [540,200]. Use a pale blue fill for Build and a
pale green fill for Review. Keep every returned object_id.
Use get_scene to verify the result, then select the Build box.

These are examples of the actual arguments the agent uses:

add_rectangle {"rect":[100,140,220,120],"fill":{"r":219,"g":234,"b":254}}
add_text {"position":[135,185],"text":"Build"}
add_rectangle {"rect":[540,140,220,120],"fill":{"r":220,"g":252,"b":231}}
add_text {"position":[575,185],"text":"Review"}
add_line {"start":[320,200],"end":[540,200]}

The board now contains five objects: two boxes, two labels, and one line. IDs are generated by the tools. The agent must use the real returned IDs when selecting or changing an object.

5. Point, ask, and inspect

Choose Select, then click the Build rectangle. Ask:

Read get_selection_context. Tell me the selected object's ID and kind.
If exactly one rectangle is selected, change its fill to pale yellow
with fill_object. Leave every other object unchanged.

The rectangle changes color in the open window. Check that the label and the Review box remain unchanged. A selection can be ambiguous when several objects overlap; use the object list or ask the agent to identify its intended object before changing it.

6. Add a human edit

Choose Line and draw a separate line below the diagram. Ask the agent to call get_scene again. It sees the new object. Press Ctrl+Z to undo that local drawing and Ctrl+Y to redo it. Local undo history is for the current window; an external edit clears obsolete history.

7. Export and reopen

Ask the agent to render the scene:

render_scene_png {"path":"/home/you/boards/first-board.png","padding":24}

Open the PNG and inspect the drawing. Close and reopen the GUI against first-board. The saved scene remains. For a complete editable backup, copy the board JSON and manifest as described in the storage guide. A PNG is a picture, not an editable board backup.

Repeat the example without a model

The machine-readable example contains executable tool calls, including canvas membership and a selection-based color change. The documentation verifier runs those calls in a temporary session:

python3 opt/boardmesh/scripts/verify_documentation.py   --bin-dir /absolute/path/boardmesh-linux-x86_64/bin

This uses an isolated directory and does not touch the board you just created. To test the desktop and agent interfaces together, run the full end-to-end verifier.
