How-to guide

Inspect and change a board with an agent

Discover before editing

  1. Confirm the active session with get_session_info.
  2. Call get_scene or get_universe to inspect current content.
  3. Call get_selection_context when the request refers to a selection.
  4. Use get_tool_help for examples or get_api_docs for the full catalog.
  5. Use the client's actual tool schema as the argument contract.

The machine-readable catalog contains the advertised input and output schemas. The HTML reference includes all 40 tools and their documented response fields.

Choose the session deliberately

MCP tools operate on the server's active session. Use create_session with make_active:true or switch_session before editing another board. Do not assume that a previous conversation still has the intended active session.

The CLI instead supports explicit session scope on each call:

boardmesh-cli get_scene --runtime-url ws://127.0.0.1:9467   --json '{"session_id":"first-board"}' --compact

Do not add a CLI-only session_id property to arbitrary MCP argument objects. Use each MCP tool's advertised schema.

Interpret selection context

The response wraps selection information under context. Useful fields include:

  • kind: no selection, one object, multiple objects, canvas selection, or a mixed selection.
  • selected_object_ids and primary_object_id.
  • selected_objects: object kind, semantic kind, optional canvas membership, connected IDs, and nearby IDs.
  • active_canvas_id and selected_canvas_ids.

Report uncertainty when the selection is empty or contains several plausible targets. Nearby objects provide context; they are not an instruction to edit every nearby object.

Draw using real IDs

Create primitives, keep each returned object_id, then use those IDs for selection, fill, duplication, visibility, locking, draw order, or deletion. Create a canvas with create_canvas and use the returned canvas_id for membership operations. Never invent an ID based on a label.

Points accept objects, two-element integer arrays, or supported coordinate strings. Rectangles accept objects, four-element arrays, or supported strings. Colors use RGB components from 0 to 255 and an optional alpha component. Use the complete schemas for edge cases.

Use supported operations

GoalTools
Drawadd_rectangle, add_circle, add_triangle, add_polygon, add_line, add_stroke, add_text
Inspectget_scene, get_universe, get_selected_objects, get_selection_context
Style and organize objectsfill_object, duplicate_object, visibility, locking, draw-order tools, and select_objects
Organize canvasescreate_canvas, set_active_canvas, select_canvases, membership assignment and clearing
Save or shareexport_scene_json, render_scene_png, render_selected_png, save_scene_as

There is no advertised MCP add_connector, add_link, set_text, or generic coordinate-update tool. The CLI has a whole-scene scene.replace operation; the MCP interface has scene import. Treat either as a full replacement and coordinate the editing turn first.

Read back and report

  1. Read the scene after a mutation.
  2. Confirm the expected objects, IDs, and fields.
  3. Render a PNG when appearance matters.
  4. Tell the person what changed, what remained, and where the export was written.

A valid tool response proves the operation completed. It does not prove that the diagram is understandable or that its technical claims are true.

Respect the caller's control

Ask for clarification before destructive changes when the request is ambiguous. Do not clear a board to make a new sketch unless the person asked for that result. Keep large imports and replacements separate from small object edits. These are agent working conventions, not an approval system implemented by Boardmesh.

Test your integration

python3 opt/boardmesh/scripts/verify_agent.py --bin-dir target/debug
python3 opt/boardmesh/scripts/verify_agent.py --bin-dir target/debug   --gui-binary target/debug/boardmesh

The first command tests MCP and CLI. The second also drives the desktop under Xvfb. Neither calls a language model. To validate this guide's example and current reference, run verify_documentation.py.
