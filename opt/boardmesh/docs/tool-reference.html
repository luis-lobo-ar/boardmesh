MCP tools and runtime methods

The MCP server advertises 40 tools. The CLI exposes 45 runtime methods. Inspect tools/list, get_tool_help, or get_api_docs when working with another build.

Each example below is an MCP tool argument object. For one-shot CLI calls, add session_id to the argument object when you need explicit session scope. MCP tools instead use the server's active session.

  • Recommended order: list_sessions/create_session/switch_session/get_session_info first, then drawing and export tools.
  • All mutating tools persist the active scene file immediately.
  • Most mutating tools return: ok, object_id when applicable, object_count, selected_object_ids, and scene_path.
  • Named sessions are the primary multi-board workflow. Raw scene-file tools and --scene mode are compatibility workflows.
  • If this server is still attached to a raw scene file, use create_session_from_scene to migrate that board into a named session before doing multi-board/session-oriented work.
  • CanvasPoint accepts {"x":380,"y":392}, [380,392], or "380,392".
  • SceneRect accepts {"x":650,"y":120,"width":150,"height":24}, [650,120,150,24], or "650,120,150,24".
  • SceneColor uses {"r":255,"g":200,"b":0,"a":255}. Use all four fields for compatibility.
  • SceneStroke uses {"color": SceneColor, "width": number}.
  • Object ids come from get_scene or get_selected_objects.
  • Triangles can be created with add_triangle(rect=...) for quick isosceles shapes or add_triangle(points=[...]) for arbitrary three-vertex shapes.
  • add_polygon(points=[...]) also accepts exactly three points if you want to model triangles as generic polygons.

Runtime-only methods: scene.get, scene.replace, session.attach, session.list, session.switch. See files and runtime reference for their request shapes.
