How-to guide

Share a board between people and agents

Use one local runtime, one explicit session, and short editing turns. The person supplies intent and judgment. The agent supplies inspection and repeatable changes.

Set up the shared workspace

  1. Choose one absolute sessions directory.
  2. Start one boardmesh-mcp authority through your MCP client.
  3. Open the GUI with the same sessions directory, session ID, and runtime URL.
  4. Check that the status bar reports the intended session and an MCP connection.
  5. Ask the agent to call get_session_info and compare the session ID and scene path.

A second agent can use the CLI against the same runtime. Give each one-shot CLI command an explicit session_id. Do not start a second MCP authority over the same files to create a second agent connection. Boardmesh does not provide a shared multi-client MCP gateway or distributed write coordination.

Use a short collaboration loop

This is a working convention. Boardmesh does not enforce a human approval step or allocate editing turns automatically.

Make “this” precise

  1. Use the desktop Select tool or object list to select the intended object.
  2. Ask the agent to call get_selection_context.
  3. Have the agent report context.kind, selected_object_ids, and the relevant object kinds.
  4. If the selection is empty or mixed, clarify before editing.
  5. Apply the requested change using the returned ID.

Canvas membership and nearby-object context help explain a selection. Connections are meaningful only when the stored scene actually contains bound connector objects. A plain line between two boxes does not establish that binding.

Choose the right kind of change

  • Use primitive tools for a new diagram.
  • Use fill_object, visibility, locking, duplication, selection, and draw-order tools for supported changes.
  • Use the GUI to drag an unlocked object.
  • For a text rewrite or arbitrary coordinate edit through the agent interface, inspect the scene and use a deliberate scene import or replacement. There is no dedicated MCP set_text or generic move_object tool in this release.
  • Before a whole-scene replacement, finish other editing turns and keep a full board backup. Scene replacement is not a merge.

Use locks with the correct expectation

A movement lock helps avoid accidental GUI dragging. It is not an access-control rule, an agent permission boundary, or a guarantee against deletion through other commands. Agree on protected objects as a team convention and review agent changes.

Understand undo during collaboration

Undo and redo belong to a desktop window's local history. A delayed echo of an acknowledged local edit preserves that history. A genuinely different external scene refresh clears obsolete undo and redo entries. After an agent changes the board, revise the change explicitly rather than assuming the GUI can undo the agent's operation.

Hand the board to another person

  1. State the session ID and sessions directory.
  2. Finish the active editing turn.
  3. Export a PNG for a quick visual summary.
  4. Copy the original board JSON and manifest for an editable handoff.
  5. Explain any manual task IDs, labels, color convention, and unresolved questions.

For remote colleagues, exchange files or images using your existing tools. The local WebSocket bridge is not a hosted room, remote identity system, or network collaboration product.

Prompt for a review turn

Inspect the current Boardmesh session and selection before editing.
Summarize what is selected and propose the smallest useful change.
Keep existing object IDs where the available tools allow it.
Do not clear the board or replace the whole scene without my instruction.
After each change, read back the scene and report what changed.
Export a PNG when the review turn is complete.
