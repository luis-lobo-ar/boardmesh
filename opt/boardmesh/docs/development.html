Maintainer guide

Build, verify, and distribute Boardmesh

Source ownership

Authoritative development is in the Mesh monorepo under opt/boardmesh. The public standalone repository is a generated distribution of that product and its required shared libraries. Integrate changes in the source authority, then regenerate the snapshot. Avoid maintaining a divergent shared-library copy inside a product mirror.

Build the current product

Use Rust 1.95 or newer. Check your compiler with rustc --version and update an older stable toolchain before building.

Run from the workspace root after following the dependency setup:

cargo build --locked -p boardmesh --bin boardmesh-cli --bin boardmesh-mcp
RUSTFLAGS='-C link-arg=-lSDL' cargo build --locked -p boardmesh --features gui

For the layout lab, run boardmesh-layout-lab after a GUI build. It isolates toolbar and docking behavior from scene editing.

Check behavior

cargo test --locked -p boardmesh
cargo clippy --locked -p boardmesh --all-targets -- -D warnings
python3 -m unittest discover -s opt/boardmesh/scripts -p 'test_*.py'
python3 opt/boardmesh/scripts/verify_agent.py --bin-dir target/debug   --gui-binary target/debug/boardmesh
python3 opt/boardmesh/scripts/verify_documentation.py --bin-dir target/debug

The Clippy command covers the default non-GUI feature set. The desktop integration requires Xvfb, xdotool, ImageMagick, and Python Xlib. Use a minimal failing case before repairing behavior, and preserve the actual board or protocol evidence.

Update API documentation

python3 opt/boardmesh/scripts/generate_tool_reference.py --bin-dir target/debug
python3 opt/boardmesh/scripts/verify_documentation.py --bin-dir target/debug

The generator reads all actual MCP tools, complete input and output schemas, examples, documented responses, and the CLI method list. It uses an isolated temporary session. Commit generated reference changes with the interface change.

Standalone source and release artifacts

The current Boardmesh export includes boardmesh, mesh-id, and mesh-graph. The shared source copies preserve one source revision and avoid requiring private Mesh access. The exported workspace builds without another Mesh product.

A maintainer exports committed files, validates the snapshot, and pushes an ordinary commit to the public repository. mesh-export.json records source revision, exporter identity, workspace membership, and file hashes. Snapshot tags identify the standalone commit. Product version 0.2.0 and snapshot identity are separate.

The release workflow tests the product and shared libraries, builds the four Linux binaries, packages provenance and notices, and verifies actual desktop and agent interaction against an extracted archive. It also validates the generated tool catalog and documentation example against the extracted binaries. It publishes an immutable prerelease only after the checks pass. A separate Pages workflow assembles only public manuals, examples, and assets, then publishes the readable documentation site.

Why shared libraries are included

The current product manifest uses local path dependencies. The export includes their transitive source closure, so the standalone clone can build. These files are generated snapshots, not independent development forks.

mesh-id deliberately remains an internal helper, with publish = false. It wraps ULID generation and preserves Mesh prefix conventions. Standalone products include a generated source copy. mesh-graph retains the existing geometry model, while Boardmesh uses the pinned third-party orthogonal router through its own compatibility adapter. No Mesh library is published to crates.io by this distribution workflow.

Contribution boundaries

Open issues against the public repository with reproducible evidence. Changes to product behavior belong in the canonical product source. Shared-library API changes need validation in every affected consumer. Keep private task state, credentials, runtime files, and personal boards out of distribution snapshots.

Mesh code is MIT-licensed. Preserve vendored wxDragon, wxWidgets, Font Awesome, and dependency license notices when distributing binaries.
