Install and verify Boardmesh

Boardmesh is a local desktop board with MCP and CLI interfaces. Its standalone repository includes the shared libraries it needs. No other Mesh application, account, database, or running service is required. Development stays in the Mesh monorepo; public releases are generated snapshots.

Download Linux binaries

Download boardmesh-linux-x86_64.tar.gz and its matching .sha256 file from the same snapshot release. Verify before extracting:

sha256sum --check boardmesh-linux-x86_64.tar.gz.sha256
tar -xzf boardmesh-linux-x86_64.tar.gz
export PATH="$PWD/boardmesh-linux-x86_64/bin:$PATH"

The archive contains boardmesh, boardmesh-mcp, boardmesh-cli, and the optional boardmesh-layout-lab. It includes source provenance and license notices. GUI executables require Linux GUI libraries, including GTK3, SDL 1.2, and OpenGL, plus a graphical display. These snapshots build on Ubuntu 24.04 for x86_64. Other platforms are not qualified by this workflow.

Snapshot releases are prereleases named for a Git commit. The package remains version 0.2.0. Optional desktop icons currently fall back to built-in shapes when the source checkout is absent; portable icon resources remain separate future work.

Use one explicit board directory

Choose a data directory outside the extracted release, so replacing binaries preserves boards. Start the MCP server through an MCP client with these executable arguments:

/absolute/path/boardmesh-linux-x86_64/bin/boardmesh-mcp \
  --sessions-dir /absolute/path/my-boards --session default

The MCP client must initialize and keep the stdio connection open. This server also starts the local WebSocket bridge at 127.0.0.1:9467. Open the GUI against that same server and directory:

boardmesh --sessions-dir /absolute/path/my-boards --session default \
  --runtime-url ws://127.0.0.1:9467
boardmesh-cli get_scene --json '{"session_id":"default"}'

Use one runtime authority per board directory. The GUI can also run alone with --no-runtime. Boardmesh is a desktop application; the WebSocket bridge is not a browser editor or a public web service. MCP help exits without creating a board; unknown arguments and options missing values fail before startup.

Build from the standalone source

Clone the public repository and run commands from its root. Non-GUI binaries need the Rust toolchain and normal Rust dependencies:

cargo build --locked --release -p boardmesh --bin boardmesh-cli --bin boardmesh-mcp
cargo test --locked -p boardmesh

For the desktop on Ubuntu, install build dependencies first:

sudo apt-get install build-essential clang cmake libclang-dev \
  libgl1-mesa-dev libglu1-mesa-dev libgtk-3-dev libsdl1.2-dev libxtst-dev pkg-config
RUSTFLAGS='-C link-arg=-lSDL' cargo build --locked --release -p boardmesh --features gui

Optional source installation of GUI and MCP, without changing your MCP client configuration:

RUSTFLAGS='-C link-arg=-lSDL' bash opt/boardmesh/install.sh --no-codex

The installer defaults to ~/.local/share/boardmesh. It creates an empty scene only on first installation and preserves existing data. Use --install-root to choose a different location. Omit --no-codex only when you want the installer to replace the existing Boardmesh registration in Codex.

Repeat the human and agent test

On Ubuntu, GUI automation needs these additional packages:

sudo apt-get install xvfb xdotool imagemagick python3-xlib
python3 opt/boardmesh/scripts/verify_agent.py \
  --bin-dir /absolute/path/boardmesh-linux-x86_64/bin \
  --gui-binary /absolute/path/boardmesh-linux-x86_64/bin/boardmesh

The agent harness initializes the real MCP protocol, discovers the tool schemas, draws a diagram, and verifies CLI visibility, canvases, selection context, malformed-input rejection, locking, visibility, separate sessions, and JSON/PNG export. The optional GUI check opens the same board under an isolated Xvfb display, observes a live agent edit, draws a human stroke, verifies undo/redo through MCP while delayed notifications arrive, closes and reopens the window, confirms a fresh live update on the reopened board, and exports the combined board. Finally it restarts MCP and checks that the entire saved universe survives.

Omit --gui-binary for the headless MCP/CLI check. The harness starts its own temporary runtime and named sessions, prints an evidence directory, and writes result.json, JSON-RPC transcripts, exports, GUI logs and screenshots. It does not edit your normal boards or require a model-provider account. A coding agent can run the harness and independently inspect the resulting board. Semantic links exist in the library model, but add_link and add_connector are not advertised MCP tools; the test uses the supported drawing tools.

Run the focused startup and installer regressions from the workspace root:

cargo test --locked -p boardmesh --test mcp_startup
python3 -m unittest discover -s opt/boardmesh/scripts -p 'test_*.py'

These checks cover the local single-runtime workflow. They do not qualify remote multi-user operation or production high availability.
