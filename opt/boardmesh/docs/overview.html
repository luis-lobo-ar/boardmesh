Explanation

What Boardmesh helps you do

A drawing can be a shared working document. Boardmesh lets a person shape the picture while an agent reads and changes its underlying objects.

A common reference for a conversation

A screenshot shows pixels. A Boardmesh scene also gives an agent object IDs, positions, text, selections, colors, and canvas membership. When you select a box and say “explain this,” the agent can call get_selection_context to identify the object instead of guessing from a screenshot.

The person decides what the picture should communicate. The agent handles repeatable work such as drawing a first draft, adding labels, applying a color convention, listing selected objects, or exporting an image. Both inspect the same saved board.

The parts and their jobs

  • boardmesh is the native desktop editor.
  • boardmesh-mcp exposes tools to an MCP client and normally hosts the local WebSocket runtime.
  • boardmesh-cli sends one command to that runtime.
  • boardmesh-layout-lab is a developer tool for testing docking and toolbar layouts.

Boardmesh does not contain a language model. Your agent client supplies the model, conversation, and any repository access. A cloud-connected agent may send board content to its provider according to that client's configuration. Local board storage does not imply that an external agent conversation stays on the machine.

What is implemented, and what is a model

AreaCurrent state
Drawing and textDesktop tools and MCP primitives create strokes, lines, rectangles, circles, triangles, polygons, and labels.
Inspection and presentationSelection context, visibility, movement locks, draw order, JSON export, and PNG export are available.
CanvasesThe universe model and MCP tools create frames and memberships. The current desktop primarily edits scene objects; the broader canvas workspace design is not fully implemented as a GUI.
Semantic connectors and routingLibrary models support bound endpoints and richer links. add_link and add_connector are not advertised MCP tools. An ordinary add_line does not bind itself to boxes. Existing orthogonal connector objects can use guarded obstacle-aware routing.
CollaborationPeople and agents share one local runtime and take turns on changes. There is no distributed merge or hosted collaboration service.
Other Mesh productsIntegrations can be built by a caller. Creating a board does not automatically create WorkMesh tasks or trigger deployments.

Where it fits

Boardmesh works well when a local diagram improves a technical conversation and you want to inspect agent changes. For a remote workshop with simultaneous editing, use a tool that already provides hosted rooms and conflict handling. For repeatable technical drawing in Boardmesh, agree on a layout and use the actual tools described in the agent guide.
